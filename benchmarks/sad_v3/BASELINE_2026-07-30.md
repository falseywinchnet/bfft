## One official DIV2K validation image

`0801.png` is 2040×1356. The fast modality processes a 768×510 image; full
processes all 2,766,240 source pixels.

| measure | fast | full |
|---|---:|---:|
| processed linear RGB PSNR | 30.383 dB | 32.416 dB |
| native-readout linear RGB PSNR | 26.754 dB | 32.416 dB |
| processed linear RGB SSIM | 0.92466 | 0.92742 |
| native-readout linear RGB SSIM | 0.77049 | 0.92742 |
| structural cells | 11,596 | 32,845 |
| texture cells | 15,458 | 76,700 |
| total v3 stream estimate | 32.836 BPP | 21.357 BPP |
| SAD 16-byte layered-site proxy | 8.841 BPP | 5.069 BPP |
| reconstruction PNG | 15.786 BPP | 13.511 BPP |
| v3 time | 670.3 ms | 5,758.5 ms |

Full uses 4.05× as many layered cells over 7.05× as many pixels. That is why
full is both more accurate and lower in bits *per pixel*, despite having a
larger absolute representation. It costs 8.59× the runtime and gains 5.66 dB
when both outputs are judged at native resolution.

## Immediate conclusion

The current cell count is competitive under SAD's site-only convention, but
v3's eight-column RGB texture basis dominates its honest storage estimate.
On Kodak, parameters cost 24.405 BPP while topology costs only 3.185 BPP.
The next compression target is therefore coefficient structure—quantization,
shared bases, and residual coding—not the label topology.

The per-image records, complete timing breakdown, and exact config are in the
ignored `results/` directory generated by `run.py`.
